# Existing lifecycle and admission priorities (D07)

This records the existing ActionManager lifecycle as an admission table; it does not introduce a parallel lifecycle enum. One `ActionManager.currentAction` owns SDK/world mutations at a time. Queued actions recheck gates after the previous transition settles, and an action replacement waits for real settlement rather than the stop request alone.

| Source or condition | Existing effect and admission | Evidence |
|---|---|---|
| Shutdown | Agent shutdown and ActionManager shutdown latch reject new messages/actions, cancel recovery/resume, stop current work, then perform owned cleanup. A queued successor cannot mutate after shutdown. | `tests/agent_shutdown.test.cjs`: `real-action-manager-cooperative-stop-and-successor-gate`; `tests/codex_session.test.cjs`: stale task result cancellation. |
| Management pause/disconnect | Management pause increments the intent epoch, closes admission, requires a fresh human intent, clears retained resume, and requests stop. Reconnection restores only the transport gate; it does not clear explicit user stop or resume old work. | `tests/management_reconnect.test.cjs`: disconnect during LLM/action, queued successor rejection, same-scope reconnect, stale restore, and fresh-intent requirements. |
| Operator fresh action intent | A current human action message advances the message generation and ActionManager intent epoch, clears the explicit user-stop latch when management permits, cancels the native model turn, and supersedes current work. Stale generation results are discarded; a replacement action is admitted only after the old body settles. | `tests/action_manager.test.cjs`: queued replacement serialization and stale action context; `tests/codex_session.test.cjs`: replacement/cancel and stale result cases. |
| Operator `!stop` | Latches `userStopped`, advances the intent epoch, cancels resume and self-prompting, and stops the current action. Existing queued work and retained resume are rejected until a later human intent is admitted. | `tests/action_manager.test.cjs`: coalesced stop, queued successor invalidation, and explicit-intent reopening; `tests/management_reconnect.test.cjs`: user stop survives reconnect. |
| Safety reflex / NPC / mode action | These callers enter through the same `ActionManager.runAction` single-action gate. A mode that interrupts an active action first requests stop and checks the captured intent epoch before starting; a concurrent operator intent makes that mode stale. Modes do not bypass shutdown, management, inventory, recovery, or user-stop gates. | `src/agent/modes.js` `execute`; `tests/action_manager.test.cjs` supersession serialization and `tests/codex_session.test.cjs` stale/stop cancellation. |
| Death / connection end | Death cancels the retained resume candidate and requests stop on the current action; a later system message may begin the existing task-thread response path. Connection end delegates to the existing agent shutdown/restart lifecycle. Death is not a persistent user-stop or management latch. | `src/agent/agent.js` death/end listeners; process shutdown and generation fixtures. No fixture establishes every simultaneous death/operator/management ordering. |
| Recovery coordinator | Recovery pauses ordinary action admission. Only an action carrying the currently active recovery admission ID can pass; recovery result events are observations and do not select a new plan. User intent, management, shutdown, death, supersession, and unconfirmed inventory remain stop/hold conditions. | `src/agent/action_manager.js` `isRecoveryAdmission`; `src/agent/agent.js` recovery generation checks; `tests/agent_shutdown.test.cjs` management/task-init invalidation and `tests/management_reconnect.test.cjs` stale-generation rejection. |
| Unconfirmed inventory | The ActionManager rejects new mutating actions while `bot.inventoryUnconfirmed` is set. This is an admission gate, not a new priority source. | `tests/action_manager.test.cjs`, crafting and interaction confirmation fixtures in the required source suite. |

Admission checks exist both before queueing and after waiting for the previous transition. Their rejected-reason strings are diagnostic; this table does not promise one total ordering for simultaneous stop causes. An already-created stop promise retains its first non-user reason; an explicit user stop may replace it. Shutdown and management latches still independently reject successor work. Unobserved combinations, including every death/operator/management race, are not claimed as verified.

The stage-four D03 required Node suite was reused as the source evidence for these existing lifecycle fixtures; it passed with exit code `0`, saved in `/tmp/mindcraft-stage4-d03-source-confirmed.exit` with full output in `/tmp/mindcraft-stage4-d03-source-confirmed.log`. D07 adds no runtime code or new suite.
