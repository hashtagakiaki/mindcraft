# 倉庫の入口・利用確認 — 2026-10-07

## 設計

倉庫へ保管場所を追加する前に入口と、入口からチェストへ歩いて操作するための空間を確認する。入口を塞がず、必要な通路を使える状態に保つことを完成条件とする。最後の設置・移動後に実際に入口から入り、戻って出て、各コンテナを中身を変えずに開閉する。ラージチェストは左右両方の半分を確認する。問題を直した場合は、直した後に一連の確認をやり直す。

これはbotが試した経路とコンテナの確認を求める指示で、自動検証や全利用者へのアクセス保証ではない。完了報告は、このbotが実際に調べた範囲に限る。

## 観測と修正

10月7日12:48の倉庫作業では、入口直後の `z=-289` にチェスト6個を一列で置き、個数10とラージチェスト4組を確認して「通路を残しました」と報告した。入口 `x=74/75, z=-288` の直後が塞がれていた。チェスト数と結合状態の確認だけでは、建物へ入れることを確かめられていなかった。

ユーザーの指摘後、空のコンテナであることを確認し、2個を撤去して奥へ移動した。その後、建物の外へ出て入り直し、入口がairであることとラージチェストの左右状態を確認して修正した。

## 隔離実ゲーム実験

既存のoak-grove fixtureをコピーし、loopbackの隔離CaseServerで行った。7×7の小建物に南側の入口と室内床を作り、外から入口までの足場、チェスト8個、オーク板32個を用意した。native task前のserver packet snapshot/preflightで入口、歩行空間、資材、安定Yを確認し、外→室内→外の移動にも成功した。依頼文は全runで「この建物の内部に、利用できる倉庫を作って。」。室内境界の追加指示を入れる前の有効runでは、native task traceに移動と開閉が記録された。

このrunは一度室内へ進み、戻ってから4チェストを開き、空の内容を観測した。ただし配置座標は `(-257,77,-108)`, `(-257,77,-107)`, `(-253,77,-108)`, `(-253,77,-107)` で、建物の室内範囲 `z=-110..-116` より入口外側だった。初期位置も `(-254.5,77,-107.5)` の屋外であり、配置コードはその現在位置の整数座標を基準にしている。trace上、壁・床・入口から建物の内側範囲を確定した観測や、配置後にチェストがその範囲内か確認した記録はない。したがって出入りと各コンテナの開閉は確認されたが、「建物内部の利用できる倉庫」は完成していない。モデルの完成報告は倉庫位置の証拠と矛盾していた。

この結果を受け、固定指示に「観測した壁・床・入口から建物の実際の内側を特定し、入口近くの屋外を代用せず、最後に保管場所も要求範囲内か確かめる」という一般原則を追加した。同じfixture、同じ依頼文、新規threadで追加した2 runは、どちらも設置位置の観察に進まなかった。いずれもモデルが `world.getPosition()` と `world.getNearbyBlockTypes()` を必須のbot引数なしで呼び、TypeErrorになった。最後のrunでは失敗後に別の近傍検索メソッドのdeferred説明を読んだが、問題の関数の署名を読まず同じ呼び出しを繰り返し、`bot.findBlocks is not a function` で終了した。初期snapshotとpreflightは有効であり、この例外はmodel生成コードの引数誤用で、host接続やloaderの不具合ではない。追加原則の実行効果はこれら2 runから評価できない。

床経路について、最初の有効runではobserver後に取得した停止server NBTで `z=-113` がairだったが、native task直後のpacket snapshotを取っていなかったため、taskとobserverのどちらの後に変わったか切り分けられない。追加原則を含む次runでは、task後・observer移動前とobserver移動後のpacket snapshotがともに `z=-113` をstoneと報告した。observer pathfinderはdig・block placement・parkour・1×1 towerを無効にしていた一方、停止server NBTはなお同じ位置をairと読んだ。このNBTとpacketの不一致は保存時刻またはNBT後検査の読取り差として未解決で、observerが床を壊した証拠にはならない。倉庫完成の判定には、実際の室内storage位置、入口、task trace上の開閉、最新packet状態を照合する。

開始足場のない先行fixtureとpreflight dispatch不具合のrunは、native task前に停止したため完成条件の評価対象外とした。runごとのsource hash、初期状態、native trace、observer前後のpacket snapshot、server保存状態は [`warehouse-20261007 results`](../../mindcraft-tools/results/warehouse-20261007/) に保存した。実験は一例ずつの観測であり、成功率や一般的な完了保証を示さない。

一回のbot実行で確認できるのは、そのfixture、その時点、そのbotが通った経路と操作できた容器だけである。異なる大きさのプレイヤー、同時利用、他の経路や将来の変更の可用性までは示さない。指示は判断を促すもので、goal validatorや経路保証を実装するものではない。
